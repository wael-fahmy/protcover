# Data

All inputs come from ProteinGym release **v1.3** (GitHub tag `PG_v1.3`, released
2025-04-28; Notin et al., NeurIPS 2023 Datasets and Benchmarks). Run
`bash data/download.sh` from the repository root to fetch everything into
`data/raw/` (gitignored, about 80 MB unpacked without the MSAs).

## Benchmark

The clinical substitutions benchmark holds ClinVar-derived missense variants
labelled Pathogenic or Benign for 2,525 human proteins, keyed by RefSeq protein
ID (`NP_...`). The reference file has no UniProt column and no MSA depth
column, so:

* `data/uniprot_map.tsv` maps RefSeq IDs to UniProtKB through the UniProt ID
  mapping API (`scripts/fetch_uniprot_map.py`, run on 2026-10-28; 2,489 of
  2,525 IDs map, reviewed human entries preferred). It is committed so the
  pipeline does not depend on the API. The RefSeq ID stays the primary key.
* MSA depth is computed from the per-sequence weights ProteinGym used for its
  clinical MSAs: `msa_neff` is the sum of weights, `msa_n_seqs` the number of
  sequences, `msa_neff_L` is `msa_neff / MSA_len`. (ProteinGym's DMS reference
  normalises by the number of well-covered columns, which the clinical
  reference does not provide.)

## Predictors and sign convention

The score files contain 30 predictors. Many come from dbNSFP and are
supervised on clinical labels (for example ClinPred, REVEL, MetaRNN, VARITY,
BayesDel), so we do not use them. We use five unsupervised zero-shot models:

| Column | Model | Type | ProteinGym directionality |
|---|---|---|---|
| `ESM1b` | ESM-1b | protein language model | +1 |
| `EVE` | EVE | MSA-based (VAE) | +1 |
| `GEMME` | GEMME | MSA-based (evolutionary) | +1 |
| `TranceptEVE_L` | TranceptEVE L | hybrid (PLM + MSA) | +1 |
| `PoET` | PoET (200M) | retrieval-augmented PLM | -1 |

The clinical score files contain no structure-aware zero-shot model, so PoET
is our "newer" model. In ProteinGym, `raw * directionality` is higher for fitter
(more benign) variants. **We store `-directionality * raw`, so in every
processed score column a higher value means more pathogenic.**
`results/sign_check.csv` confirms the orientation: the per-protein mean AUC
under our convention reproduces ProteinGym's published value to three decimals
for all five predictors.

## Processed tables (`data/processed/`, regenerated by the scripts)

* `variants.parquet`: `protein_id, uniprot, variant, position, label` (1 =
  pathogenic) and one oriented score column per predictor. 62,727 rows, no
  missing scores.
* `proteins.parquet`: label-free per-protein metadata (sequence, length, MSA
  depth, number of scored variants, UniProt accession, gene).
* `families.parquet`: family assignments (see `scripts/build_families.py`).
* `homology.parquet`: all-vs-all MMseqs2 hits (E <= 10, self hits removed).
